## 1. Context Engineering

### Context Window

A context window is the amount of information a language model can process at one time.

Common context window sizes include:

* 4K tokens
* 8K tokens
* 128K tokens

When working with large conversations or documents, the context should be managed carefully to avoid exceeding the model's limit.

### Dynamic Context Injection

Dynamic context injection means adding relevant information to the prompt at inference time.

In a RAG system, relevant documents can be retrieved and added to the context before generating the answer.

### Memory Types

I studied different types of conversational memory:

* Conversation Buffer Memory – stores previous messages.
* Summary Memory – summarizes older conversations.
* Entity Memory – stores important information about entities mentioned during conversations.

### Context Compression

Context compression reduces the amount of information sent to the model.

A common strategy is:

* Keep recent conversations in detail.
* Summarize older conversations.
* Remove irrelevant information.

This helps keep the context within the model's token limit.

# 4. Why FastAPI for AI Applications?

FastAPI is useful for AI applications because:

* AI models can be exposed through API endpoints.
* Async programming can help handle long-running operations.
* Pydantic provides structured input validation.
* Automatic API documentation makes testing easier.
* It can integrate with RAG pipelines and LLM services.
* It is suitable for building production-oriented APIs.

The application includes the following endpoints:

# 6. Pydantic Validation

Pydantic was used to define structured request and response models.

For example:

```python
class Item(BaseModel):
    name: str
    description: str
    price: float
```

This ensures that API input follows the expected structure and data types.

# 7. Task 3 – RAG API Endpoint

I created a POST endpoint:

```text
POST /ask
```

It accepts a question and processes it through the RAG pipeline.

The basic flow is:

```text
User Question
      ↓
Retrieve Relevant Documents
      ↓
Generate Answer
      ↓
Return Response
```

The response contains:

```json
{
  "answer": "...",
  "sources": ["rag_basics.txt"],
  "confidence": 0.8
}
```

---

# 8. RAG System Startup

The RAG system is loaded during application startup instead of loading it for every request.

This improves efficiency because the RAG system does not need to be initialized repeatedly.

The startup flow is:

```text
FastAPI starts
      ↓
Load RAG system
      ↓
Application ready
      ↓
Accept requests
```
